# Determinism baseline audit

## Scope and source revisions

This audit used the three existing development seeds **10101, 691153, 260679** for **2,000 ticks** each. No ecology tuning or long benchmark was run. The archived [optimization trajectory hashes](data/optimization_trajectory_final.json) were generated by `scripts/verify_optimization_trajectory.ts` on revision `50208b1`; all six archived Model 0/1 hashes reproduce exactly from that detached revision with the current installed dependencies. The archive first appeared in Git at `50208b1` and was moved, unchanged, at `054e9e1`.

All six ordinary Model 0/1 hashes from committed `054e9e1` equal those from the current working tree. The uncommitted predator placement, feeding observer, and generation edits therefore do not explain the mismatch. The hash input is `JSON.stringify(serializeForStorage())` after deleting only `createdTimestamp` and `lastSavedTimestamp`. It includes ecological state, PRNG state, organism IDs, ordered events, configuration, and statistics. Counts alone cannot establish equivalence.

## Root cause

The exact divergence is commit **`054e9e1`**, which corrected reproduction accounting. Comparing the complete six serialized states from `50208b1` and the current tree at tick 2,000 found one differing path in each: `stats.energyLedger.dissipatedReproductionTax`. The prior values were **100, 1,246, 1,468** for Model 0 and **1,139, 2,905, 2,510** for Model 1 in seed order above; current values are **76, 942, 1,164** and **869, 2,217, 1,931**. No other serialized field differed. The earlier ledger estimated newborn reserve from parent cost; `054e9e1` books actual newborn reserve after a successful birth. The correction is intentional and documented in the [predator energy audit](PREDATOR_ENERGY_AUDIT.md). It did not change these worlds' ecological trajectory, RNG, or event order. Historical save ledgers retain their old cumulative amounts and use the corrected calculation for subsequent births; they are not rewritten.

No dependency or test-configuration difference was needed to reproduce the archive. The original hash script's only change at `054e9e1` was its default output path. The earlier revision is available, so no historical source gap remains for these six references.

## Current baseline and replay checks

The [version 2 baseline](data/determinism_baseline_v2.json) anchors the current `054e9e1` ordinary behavior for Models **0, 1, 2** on the same three seeds at tick 2,000. `scripts/verify_determinism_baseline.ts` hashes every saved field except the two timestamps. For each of nine model/seed cases, it compares full serialized state and generated terrain cells between independent fresh engines at ticks 0, 1,000, 1,500, and 2,000. A save at tick 1,000 is cloned and restored, then its state is compared with uninterrupted execution at the same checkpoints. These comparisons cover organisms and IDs, resources, terrain and patches, climate, species and ancestry, event order and IDs, mutation history, PRNG, ecology configuration, and all saved statistics. The development placement option is supplied to each restored world to verify it is ignored there.

The verifier also checks that old version-2 saves lacking all ecology metadata, or only the behavior-model key, validate and resolve to Model 0 with the intended legacy carrion reach. Each continues for 50 ticks identically to an explicitly equivalent Model 0 save. The production default equals explicit Model 0. The placement option leaves new Model 0 and Model 2 worlds unchanged through 50 ticks; existing focused placement tests cover ordinary versus placement-enabled Model 1 creation and restored Model 0/1/2 continuation. Experimental reproduction and food-override hooks remain unset in ordinary runs and are not persisted. Model 1 and Model 2 remain opt-in and retain their saved model selection.

As a separate cross-revision check, actual tick-1,000 saves made at `50208b1` for seed 10101 under each of Models 0–2 validated and loaded in the current tree with their saved model selection. After 500 more ticks, their complete saved states matched continuations made at `50208b1` except for the corrected cumulative reproduction-tax ledger. This tests older revision saves directly; no archived user save corpus was available.

The new baseline is a **revision-specific regression reference**, not evidence for ecological quality or cross-version byte equivalence. Future intentional save-statistic or mechanics changes require a new versioned reference and an explained diff; the archived version 1 hashes remain intact.

## Verification

Run `./node_modules/.bin/tsx scripts/verify_determinism_baseline.ts` from the repository root to compare against the version 2 reference. The completed verification passed all nine 2,000-tick trajectories, independent fresh repeats, and mid-run saves. Focused tests passed **23/23**; the full suite passed **106/106**. `npm run lint`, `npm run build`, and `git diff --check` passed. These results use the three named development seeds; they do not establish broader ecological quality or cross-platform equivalence.
